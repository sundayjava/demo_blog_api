SETUP INSTRUCTIONS
------------------

1. CREATE PROJECT DIRECTORY
   mkdir blog-api
   cd blog-api

2. CREATE ALL DIRECTORIES
   mkdir -p .github/workflows
   mkdir -p config
   mkdir -p migrations
   mkdir -p src/{config,db/repository,handlers,middleware,models,services}
   mkdir -p tests/{common,integration}

3. COPY ALL FILE CONTENTS
   Copy each file from the artifacts into the appropriate location

4. MAKE SCRIPTS EXECUTABLE
   chmod +x setup.sh

5. VERIFY FILE COUNT
   find . -type f | wc -l
   # Should show 49 files (excluding any .git files)

6. RUN SETUP SCRIPT
   ./setup.sh

7. OR MANUAL SETUP
   # Copy .env.example to .env
   cp .env.example .env
   
   # Install sqlx-cli
   cargo install sqlx-cli --no-default-features --features postgres
   
   # Start databases
   docker-compose -f docker-compose.dev.yml up -d
   
   # Run migrations
   sqlx migrate run
   
   # Build and run
   cargo run

VERIFICATION CHECKLIST
----------------------

After creating all files, verify:

□ cargo check passes without errors
□ All mod.rs files correctly declare submodules
□ Database migrations are numbered correctly
□ .env file exists and is configured
□ PostgreSQL containers start successfully
□ Migrations run without errors
□ cargo build completes successfully
□ cargo test passes (after DB setup)
□ cargo run starts the server
□ Health check responds: curl http://localhost:8080/health

CRITICAL FILES THAT MUST BE CORRECT
------------------------------------

These files are interconnected and must all be present:

1. src/main.rs - Entry point, imports all modules
2. src/routes.rs - Route configuration, uses handlers
3. src/services/jwt.rs - JWT service (WAS MISSING!)
4. src/middleware/auth.rs - Uses jwt.rs for auth
5. All mod.rs files - Must declare submodules correctly

COMMON ERRORS AND FIXES
------------------------

ERROR: "cannot find module X"
FIX: Check that mod.rs exists and declares the module

ERROR: "cannot find type Y in this scope"
FIX: Add proper import: use crate::models::Y;

ERROR: "migration failed"
FIX: Ensure database is running and migrations are in order

ERROR: "address already in use"
FIX: Kill existing process: lsof -ti:8080 | xargs kill -9
